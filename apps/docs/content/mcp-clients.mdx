The dashboard's **Connections** page shows these commands with your own
endpoint already filled in. Open it at `/org/<your-organization>/connect` on
**Cloud** and **Self-host**, or **Connections** (`/connections`) in the **Local** dashboard. Copy the endpoint for your running server into your MCP client. For hosted OAuth, your client must be able to reach the server and you need membership in the organization you select.

Verify the connection by finding and running an available read tool in an app the connection can use, with its required account linked.

| Where | MCP endpoint |
| --- | --- |
| **Cloud** | `https://mcp.executor.sh/mcp` (separate from the dashboard origin `https://app.executor.sh`) |
| **Self-host** | `<your origin>/mcp` |
| **Local** | `http://127.0.0.1:4312/mcp` |

On **Cloud** and **Self-host**, you can also connect with a [personal access token](/docs/api-keys#connect-an-mcp-client) as the `Authorization: Bearer` header on `<mcp-origin>/org/<organization>/mcp`. The **Personal access token** tab on an organization's **Connections** page shows that address filled in.

**Approval defaults:** The browser OAuth consent screen preselects **Automatic** for the default MCP URL, which accepts app approval requests without a separate Executor prompt. See [Choosing where approvals appear](/docs/mcp-clients#choosing-where-approvals-appear) for the other modes.

Most clients load MCP servers only at startup. After you add Executor, restart
the client or open a new session before its tools appear.

Moving from a local Executor or Executor 1 to a self-hosted server? Remove the
old entry first before adding your self-hosted endpoint.

## ChatGPT

For Executor Cloud, [open the Executor plugin](https://chatgpt.com/plugins/plugin_asdk_app_6acd465c1d148191832781c3c8ab4d99)
and click **Install plugin**. Connect the included Executor app when prompted,
sign in to Executor, choose your team and approve access. Installation and
account authorization are separate steps; you may be asked to connect on first use.

Start a new chat and ask: **Show me the apps and tools available in my Executor workspace.**
If your workspace prevents installation, ask your admin to allow Executor.

For Self-host or a scoped MCP URL, confirm that your ChatGPT workspace allows
custom MCP servers and that ChatGPT can reach your server, then use
**Plugins → Add → Add custom MCP server**. Name it **Executor**, enter your
endpoint, choose **OAuth**, then click **Create as a plugin** and **Connect**.
Sign in and approve access.

## Codex

In the ChatGPT desktop app, open the same
[Executor plugin](https://chatgpt.com/plugins/plugin_asdk_app_6acd465c1d148191832781c3c8ab4d99),
install it and connect your Executor account when prompted. Start a new Codex
session and ask it to show the apps and tools in your Executor workspace.

In Codex CLI, run `/plugins`, find Executor in the plugin browser and install it.
Start a new session to load its skills and tools, and complete sign-in when prompted.
Marketplace availability depends on your Codex environment.

The IDE extension does not support plugins. For the IDE extension, Self-host,
or a scoped connection, add the MCP server directly:

```bash
codex mcp add executor --url 'https://mcp.executor.sh/mcp'
codex mcp login executor
```

Replace the URL with your own endpoint when needed. Sign in to Executor,
choose your team and approve access, then start a new session.

See [OpenAI's plugin guide](https://learn.chatgpt.com/docs/plugins) for supported
surfaces and installation details.

## Cursor and other clients

Use the installer. It detects the client and writes its configuration for you.

<CodeGroup>

```bash Installer
npx add-mcp 'https://mcp.executor.sh/mcp' --transport http --name executor
```

```json By hand
{
  "mcpServers": {
    "executor": {
      "type": "http",
      "url": "https://mcp.executor.sh/mcp"
    }
  }
}
```

</CodeGroup>

If your client does not accept the installer, merge the configuration above into
its MCP file by hand.

Clients that support this format read a `mcpServers` map, and
Executor needs nothing beyond a streamable HTTP URL. Sign-in happens in your
browser the first time the client connects.

## Connecting to a local server

A local server also signs clients in through your browser, using the dashboard
you paired with `executor`. A client that cannot sign in can send the local API
key as a bearer token instead (note: the bare Local server key defaults to model
approval mode). The port is `4312` unless you changed it with
`executor service set port`:

<CodeGroup>

```bash Installer
npx add-mcp 'http://127.0.0.1:4312/mcp' --transport http --name executor \
  --header 'Authorization: Bearer <key>'
```

```json By hand
{
  "mcpServers": {
    "executor": {
      "type": "http",
      "url": "http://127.0.0.1:4312/mcp",
      "headers": {
        "Authorization": "Bearer <key>"
      }
    }
  }
}
```

</CodeGroup>

The background Executor keeps running until you stop it, but it does not start
with your computer: after a restart, run `executor` or `executor service start`,
or the client's connection is refused.

## Scoped connections

Use **Connections** to manage named MCP connections with their own app, tool and account policy. A scoped URL uses OAuth. Scoped edits apply on later authorization checks, including for agents with an existing grant. Revoking a grant or connection blocks subsequent requests that use it.

## Choosing where approvals appear

The browser OAuth consent screen preselects **Automatic** for the default MCP URL,
which accepts app approval requests without a separate Executor prompt. To use model
mode, select **Through your agent** on the consent screen to let the client answer
and resume. Select **In your browser** to answer from the credential owner's
signed-in hosted browser or a paired Local browser. A URL with
`?elicitation_mode=browser` or `?elicitation_mode=native` can preselect that option.

For browser approvals, use:

```bash
claude mcp add --transport http --scope user executor 'https://mcp.executor.sh/mcp?elicitation_mode=browser'
```

OAuth keeps the mode you approved until you connect again with a new grant. A
hosted personal access token defaults to automatic and accepts
`?elicitation_mode=model`, `?elicitation_mode=native`, or
`?elicitation_mode=browser` in its MCP URL; the bare Local server key defaults to
model mode. See [what happens when a tool requests approval](/docs/concepts/tools-and-approvals#what-happens-when-a-tool-requests-approval) for each mode.

## Check that it worked

On Local, or on a hosted connection with access to the built-in Executor app and its linked service account, ask the agent to run this:

```js
return await tools.search({ query: "Executor" });
```

Look for callable paths for the Executor app, then run an available read tool. For a connection without that app, find and run a read tool from another allowed app with its required account linked.
