The `executor` command runs Executor on your machine (**Local**) for one person and also acts as a shell and stdio MCP client for **Local**, **Self-host**, and **Cloud** Executor hosts.

Install the beta release with `npm i -g executor@beta` (Node 14.18.0 or newer; a bare `npm i -g executor` installs v1.6.11 without apps), or use the install script or Homebrew without Node. With the default service settings, `executor` starts the background server and opens the dashboard.

**Prerequisites:** macOS (Apple Silicon or Intel), Linux with glibc (ARM64 or x64) and system CA certificates installed, or Windows (x64). For npm, keep Node.js 14.18.0 or newer on `PATH` — the npm launcher uses Node to start Executor's bundled native runtime. The standalone installers and Homebrew run without a separate Node or Bun installation.

**You'll know it worked when** `executor --version` prints `executor v2.0.0-beta.79` and `executor` opens the dashboard in your browser (or, on a headless machine, prints a one-use connection link valid for five minutes).

After installing with the standalone script or Homebrew, follow any `PATH` instructions and open a new terminal. Check the installed version, then start Executor:

```bash
executor --version
executor
```

With the default service settings, `executor` starts the background Executor if it is not running, opens the dashboard in your browser, and exits. If `executor` cannot launch a browser, open the one-use connection link it prints within five minutes; on a headless machine, use `executor service start` and `executor service pair`. Executor ships as one executable with its runtime, dashboard, Git, and workerd beside it.

- **npm launcher:** Keeps Node.js 14.18.0 or newer on `PATH` to launch the native runtime. The first time a version runs, it downloads that release's platform archive from the public GitHub release, verifies its SHA-256 checksum against the npm manifest, and caches it in `~/.executor/v2/launcher/<version>`. Set `EXECUTOR_DOWNLOAD_URL` to point at a release mirror.
- **Install script:** Keeps each release under `~/.executor/v2/runtime/versions/`, points `~/.executor/v2/runtime/current` at the active version, and links `~/.local/bin/executor` to it on macOS and Linux (printing `PATH` instructions if `~/.local/bin` is not already on your `PATH`, without editing your shell profile). On Windows, the script adds `%USERPROFILE%\.executor\v2\runtime\current` to your user `PATH` (unless `EXECUTOR_NO_MODIFY_PATH` is set) and instructs you to open a new terminal. Pass a version argument to install a specific release, for example `curl -fsSL https://executor.sh/docs/install.sh | sh -s -- 2.0.0-beta.79`.
- **Desktop app:** If you prefer a window over a browser tab, install the desktop app — it shares the same background server and `~/.executor/v2/cli` data directory by default (desktop can override its directory).

## Commands

| Command | Purpose |
| --- | --- |
| `executor` | With the default service settings, start the background Executor if it is not running, open the dashboard, and exit. Accepts `--standalone` and `--server <url>`. |
| `executor serve` | Run Executor in the current terminal without opening a browser until you press Ctrl+C. |
| `executor service` | Start, stop, restart, inspect, and configure the background Executor; print a connection link or rotate its local API key. |
| `executor login`, `executor apps login`, `executor logout`, `executor whoami` | Sign in to a **Self-host** or **Cloud** host for tool commands or app commands, sign out, and inspect the active sign-in. |
| `executor search`, `describe`, `call`, `execute`, `resume`, `skills` | Search, inspect, and call app tools and skills from a shell. |
| `executor mcp` | Serve the resolved host's MCP endpoint to an MCP client over stdio. |
| `executor apps` | Create, edit, deploy, share, and install apps. See [Author an app](/docs/author-an-app). |
| `executor upgrade` | Install the newest release on your channel, or switch back with `--rollback`. |

All subcommands also accept `--help` (`-h`), `--version` (`-v`), `--wizard`, `--completions <bash|zsh|fish|powershell|sh|pwsh>`, and `--log-level <level>`.

## The background Executor

By default, local commands and the desktop app share one background server per data directory. Manage it with `executor service start`, `stop`, `restart`, `status`, `get`, `set`, `unset`, `pair`, and `rotate-key`. See [Background server and key storage](/docs/run/cli/background-server).

## Configure it

Set `EXECUTOR_PORT`, `EXECUTOR_DATA_DIR`, `EXECUTOR_KEY_STORAGE`, `EXECUTOR_API_KEY`, `EXECUTOR_ENCRYPTION_KEY`, `EXECUTOR_BROWSER_ORIGIN`, `EXECUTOR_WEBHOOK_ORIGIN`, `EXECUTOR_NO_UPDATE_CHECK`, or `DO_NOT_TRACK` / `EXECUTOR_DISABLE_ANALYTICS` to customize the local server. See [Background server and key storage](/docs/run/cli/background-server#configure-it).

## Use your tools from a shell

For **Cloud** and **Self-host**, use `executor login` for tools and MCP and `executor apps login` for app commands. Pass `--host <your Self-host origin>` for Self-host. With no target host selected, tool and app commands and the stdio bridge use Local. See [background service settings](/docs/run/cli/background-server#settings-stored-in-servicejson) for standalone mode. Run `executor search`, `describe`, `call`, `execute`, `resume`, and `skills` from any shell. See [Use Executor from a shell](/docs/run/cli/from-a-shell).

### Serve your tools to an MCP client

Run `executor mcp` to bridge the resolved host's MCP endpoint over stdio for clients that launch a command, such as `claude mcp add executor -- executor mcp`. See [Use Executor from a shell](/docs/run/cli/from-a-shell#serve-your-tools-to-an-mcp-client).

## Connect an agent

In the local dashboard, open **Connections**, choose a connection such as **Full access**, and click **Connect** to add the local MCP endpoint to Claude Code, Cursor, or Codex, or bridge it over stdio with `executor mcp`. After a reboot, run `executor service start` before using a direct Local HTTP connection configured for the background server. See [Add an MCP client](/docs/mcp-clients).

## Coming from Executor 1

If `executor --version` still prints v1, another installation is earlier on your `PATH`, and Executor 1 commands such as `web`, `daemon`, `tools`, and `server` have moved to new names. See [Upgrade and migrate from Executor 1](/docs/run/cli/upgrade#coming-from-executor-1).

## Back up and update

Back up the Local data directory (default `~/.executor/v2/cli`) together with its matching key source: the OS credential, the `keys.json` inside the directory, or both original supplied keys, according to how the installation was configured. Update with `executor upgrade` or roll back a standalone install with `executor upgrade --rollback`. See [Upgrade and migrate from Executor 1](/docs/run/cli/upgrade) and [Background server and key storage](/docs/run/cli/background-server#back-up-your-data-and-keys).

## Limits

- Running `npm i -g executor` without `@beta` installs Executor v1 (`1.6.11`), which does not support apps or Executor 2 commands.
- Linux installs require glibc (musl distributions such as Alpine are not supported) and system CA certificates installed.
- The background Executor does not register with your OS service manager, so it does not start automatically on boot.
